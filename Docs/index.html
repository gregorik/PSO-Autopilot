PSO Autopilot (Core) Manual

Welcome to PSO Autopilot Core — the open-source, memory-safe shader compilation and PSO warm-up architecture for Unreal Engine 5.

Most generic shader precache solutions attempt to eliminate stutter by bulk-loading every asset in the project simultaneously. In large open-world or content-heavy projects (10GB–100GB+), this primitive approach causes massive RAM spikes, freezes loading screens completely, and triggers Out-Of-Memory (OOM) crashes on consoles and mid-range PCs.

PSO Autopilot Core solves this. By streaming materials in controlled, asynchronous batches and releasing them before the next batch loads, your memory usage stays completely flat while driver shader caches are populated.

2. Core Architecture & Pillars

Pillar 1: Memory-Safe Asynchronous Chunking

Instead of loading thousands of assets at once, PSO Autopilot Core uses Unreal's native FStreamableManager to stream materials in batches (e.g., 100 assets at a time). When a batch finishes loading, driver shader compilation is triggered asynchronously in the background via Material->CacheShaders(EMaterialShaderPrecompileMode::Background).

Discovered Assets
↓
Slice Batch (100) → Async Stream (FStreamableManager) → Trigger Driver Compile
↓
Wait on Queue (Bounded 30s) → Release Handles → Force Garbage Collection
↓
Next Batch (Memory Remains Flat)

Pillar 2: Non-Blocking Garbage Collection Sweeps

Between batches, PSO Autopilot Core explicitly resets streamable handles, unbinds loaded asset pointers, and requests a garbage collection sweep via GEngine->ForceGarbageCollection(false). This ensures physical RAM does not accumulate during the warmup process.

Pillar 3: Resilient Queue Drain Protection

When the engine's FShaderPipelineCache compiles PSOs, Core monitors NumPrecompilesRemaining(). To ensure your loading screen can never hang indefinitely if the graphics driver stalls or finishes asynchronously, Core enforces a 30-second bounded timeout before cleanly proceeding.

4. Quick Start Guide

  1. Copy or clone the PSOAutopilotCore folder into your project's Plugins/ directory.
  2. Open your project in Unreal Engine (compatible with UE 5.5, 5.6, 5.7, 5.8+).
  3. Go to Edit > Project Settings > PSO Autopilot Core.
  4. Set your Directories To Scan (e.g. /Game or /Game/Characters, /Game/Environments).
  5. In your Loading Screen Blueprint or GameInstance:
    • Call Get Game Instance Subsystem → select PSO Autopilot Core Subsystem.
    • Bind to On Progress Updated to update your progress bar and status text.
    • Bind to On Warmup Complete to open your gameplay level.
    • Call Start Warmup.

5. Project Settings

Configured in Edit > Project Settings > PSO Autopilot Core:

Directories To Scan

An array of paths (e.g., /Game, /Game/Materials). The plugin recursively searches these paths for UMaterialInterface assets. Leading/trailing whitespace and slashes are automatically sanitized.

Batch Size

Default: 100 (Clamped 10–1000). The number of material assets streamed and compiled concurrently in a single batch. Lower this to 50 on memory-constrained mobile devices or low-RAM platforms.

bGarbageCollectBetweenBatches

Default: True. Requests a non-blocking garbage collection pass after every batch is unloaded to ensure RAM usage stays low and flat.

6. UI & Blueprint Integration

The UPSOAutopilotCoreSubsystem provides two primary dynamic multicast delegates:

On Progress Updated

Fires during scanning, batch loading, and completion to drive your UI:

  • OverallProgress (float): Normalized value from 0.0 to 1.0. Bind directly to a UMG ProgressBar.
  • CurrentStatusMessage (string): Human-readable status message (e.g., "Scanning for Assets...", "Loading Batch of 100 Assets...", "Compiling Shaders...", "Clearing Memory...").

On Warmup Complete

Fires once when all batches have finished and the pipeline queue has settled. Bind this to remove the loading widget and call OpenLevel.

7. Blueprint Telemetry API

The subsystem provides convenient BlueprintPure functions for inspecting the warmup cycle:

// Check if warmup is currently active
bool IsWarmingUp = PSOSubsystem->IsWarmingUp();

// Get the current state enum (Idle, Scanning, LoadingBatch, ProcessingBatch, UnloadingBatch, WaitingForGC, Finished)
EPSOWarmupState State = PSOSubsystem->GetWarmupState();

// Get overall progress (0.0 to 1.0)
float Progress = PSOSubsystem->GetOverallProgress();

// Discovered asset counts
int32 Total = PSOSubsystem->GetTotalAssetsToProcess();
int32 Processed = PSOSubsystem->GetTotalAssetsProcessed();

// Latest status text
FString Status = PSOSubsystem->GetCurrentStatusMessage();

8. Setting up the Demo

PSO Autopilot Core includes helper classes to quickly verify warmup behavior:

  1. Create a Widget Blueprint (e.g. WBP_PSOAutopilotCoreHUD) and reparent it to PSOAutopilotCoreDemoWidget.
  2. In the Widget Designer, add the following widgets with exact matching names:
    • ProgressBar (ProgressBar)
    • StatusText (TextBlock)
    • TimerText (TextBlock)
    • SpinnerImage (Image)
  3. In your level, place a PSOAutopilotCoreDemoManager actor and assign your widget class to HUDClass.
  4. Press Play to watch the batch progress, timer, and memory lifecycle in real time.

9. Troubleshooting

Q: The progress bar stays at 0% for a moment on boot.

A: Unreal Engine's Asset Registry initializes asynchronously during startup. PSO Autopilot Core waits for the registry to finish before querying assets to avoid missing unindexed materials.

Q: How do I test in a real packaged environment?

A: Shader compilation and PSO caching operate differently in Packaged builds than in the Editor. Ensure bShareMaterialShaderCode=True is enabled in your project packaging settings and test with a Shipping or Development packaged build.

Q: How can I achieve 60fps smooth loading UI without hitches?

A: PSO Autopilot Core focuses on memory safety and yields between batches. If you need intra-frame time-sliced yielding, frame pacing, and smart cache skipping for sub-frame smooth loading transitions, upgrade to the Pro Version on Fab.
